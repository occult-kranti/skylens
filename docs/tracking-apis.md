# Tracking sources, delivery checks and limits

Researched **2026-10-05** against the primary sources linked below. Source documentation, payload retrieval, browser delivery, and physical camera alignment are separate evidence. This catalogue covers the application's useful tracking workflows; it does not claim coverage of every object or every API.

### Rate-limit headers and browser access

The AvioADSB documentation defines `X-RateLimit-Reset` as **“Seconds until the quota resets”**, not Unix epoch seconds. `Retry-After` is documented as seconds on 429 responses. `X-RateLimit-Remaining` is requests left in the applicable period. Browser JavaScript can read these custom response headers only if the provider includes them in `Access-Control-Expose-Headers`. A Node HTTP client can see headers that application JavaScript cannot; release evidence must distinguish the two.

An anonymous user's network may share its quota with other users. A local request counter cannot promise server-side remaining quota. If quota headers are unavailable, show unknown quota and use a conservative cooldown after a limit response. Do not call a waiting state “live.” A user can stop the feed at any time; stop on backgrounding or simulated time and release timers and pending requests. Provider failures must leave local astronomy and manual exploration usable.

CelesTrak's policy requires stopping on non-200 responses. The loader therefore requests groups sequentially and stops on the first error, including an invalid payload. Attempts reserve and persist a two-hour interval before the first request. Cancelled requests keep that reservation because the server may already have processed the request. Concurrent controls share one request sequence. A partial successful response is usable with explicit missing-group metadata; it does not overwrite the last complete persisted cache. On full failure, an older successful cache is preferred to the bundled snapshot. Snapshot retrieval time is never relabelled as a successful online fetch.

Current online requests use OMM-keyed JSON with satellite.js 7.1.0 and full catalogue identifiers, verified against independent SGP4 vectors. TLE remains only a legacy cache/snapshot format. Group coverage is still stations + visual, not the entire satellite catalogue. See [the current aircraft comparison](aircraft-nearby-sources.md) and [satellite methods](satellite-nearby-methods.md). Aircraft reports older than20 seconds cannot guide or draw sky overlays even while retained in the list up to60 seconds.

## Delivery evidence and reproducible check

`tests/live-feeds.mjs` is an **optional, non-blocking diagnostic**, separate from deterministic tests. It uses only fixed public endpoints and a fixed London test location, no tokens and no personal coordinates. Each endpoint receives at most one GET, with a five-second deadline and no retry. It writes `test-results/live-feeds.json`; preserve that file as a CI artifact rather than committing a changing live payload.

```sh
# Offline diagnostic parser/metadata checks: no external requests.
node tests/live-feeds.mjs --self-test

# Preferred release check after Playwright/Chromium setup: actual browser CORS.
node tests/live-feeds.mjs --browser

# Alternative when no browser is available: HTTP/headers only, not browser proof.
node tests/live-feeds.mjs
```

Choose **one network mode**, not both. Respect CelesTrak's two-hour request interval across manual diagnostic runs and CI reruns. Browser mode uses a minimal synthetic page with the actual Pages security origin `https://occult-kranti.github.io`, blocks unrelated requests and performs real browser fetches. It does not claim that the public deployment itself contains the changes. The report distinguishes privileged observed HTTP headers from the headers exposed to page JavaScript, includes `browserReadable`, provider timestamp, count, oldest/newest orbital epoch and stale element count, and records transport/HTTP/parse errors without making the deterministic build fail.

Local check **2026-10-05 05:21:17 UTC**: both Node requests failed before any HTTP response (`TypeError: fetch failed`) in this restricted workspace. No HTTP status, CORS permission or live data freshness was verified. This is an execution-environment delivery failure, not evidence that either provider is globally down. The artifact records both failures. The later CI/browser artifact is the source of truth for release delivery.

Exa source retrieval on the same research date returned a syntactically valid CelesTrak stations listing and a valid empty AvioADSB point response. The retrieved ISS element epoch was 2026-08-22, which is too old for current rendering under the seven-day display policy. Research retrieval can cache pages and exposes no browser CORS proof; it cannot establish current upstream orbital freshness. That data was not copied into the application as a fresh snapshot. An empty aircraft response is valid community coverage, not proof that no aircraft are present.

## Deterministic validation and remaining acceptance gates

`node tests/tracking-status.mjs` passes eleven policy/lifecycle cases: shared concurrent requests, successful-cache reuse, persisted 403 cooldown across reload, expiry/recovery, explicit partial groups without destroying a complete cache, invalid-payload failure, truthful local fallback and orbital-age suppression, blocked storage, provider/fallback cancellation, rapid return after background cancellation and corrupt stored records. `node tests/live-feeds.mjs --self-test` passes fourteen offline assertions including stale epochs, missing/future aircraft timestamps, empty coverage, 429 metadata and the distinction between observed CORS headers and browser delivery.

Before claiming a live provider works for the release, inspect the uploaded report: actual browser-readable 200, valid payload, plausible provider timestamp/element epochs, applicable quota-header exposure, and expected empty/error UI. Test from the deployed HTTPS origin on a phone as well: opt-in disclosure, background/return, network loss, permission changes and disabling each feed. Those checks do not prove physical camera alignment, satellite brightness, comprehensive aircraft coverage, or visual recognition.
