## Consolidated priority / acceptance guidance

1. **P0 correctness and permission failures:** one shared observer and UTC instant; preserve explicit manual location/time. Reject invalid dates/coordinates, distinguish unknown birth time, missing sensor heading and below-horizon objects. Polar no-event returns a meaningful result, not fabricated times.
2. **P1 camera-first sky:** start camera by user gesture; rear preference, actual video crop/aspect and screen orientation in projection; full rotation basis with heading correction and estimated FOV. Motion metadata must describe measured/relative/uncertain north. Release tracks/listeners/loops on stop/unmount and suspend while backgrounded. DOM-accessible equivalent object list plus search and selection. Only physical phone tests prove alignment.
3. **P1 common astronomical tasks:** same positions power Sky, observing list, planetary details, Moon illumination, twilight and time travel. Use topocentric apparent horizon coordinates for sky; geocentric ecliptic longitudes for astrology where tradition requires them. Avoid mixing these frames.
4. **P1 honest charts/calendar tools:** isolate traditional conventions from astronomical core. Houses and ascendant only when birth time/location are known. Report zodiac, ayanamsha, house method, aspect orbs and supported date range. Do not bolt on multiple ephemerides to achieve broad labels. DST folds/gaps must be rejected or resolved explicitly. Named calendar variants and local-observation differences belong near results.
5. **P2 saved observation workflow and educational simulation:** local notes/favourites/location snapshots, transparent orbit scale/unit/time controls, offline only once verified. Data licensing applies individually to star lists, constellation geometry, textures and interpretations.
6. **P2/P3 resource-heavy extensions:** satellite feed, weather, global event feeds, plate solving, telescope control and billion-star maps require separate data/reliability/performance gates. No fabricated fallback output when those dependencies fail.

## Integration architecture recommendation

Use a small immutable observation context (UTC instant, latitude north/east longitude, elevation metres, Live/Simulated state) and a shared Astronomy Engine adapter. Compute solar-system ephemeris at a slow documented cadence; rotate/project cached vectors as orientation frames arrive. A view can use the same observer context while a natal chart owns a separate explicit input snapshot. Traditional methods consume core quantities without modifying them. Keep event searches off sensor-frame callbacks; batch/cancel when date/location changes. Measure browser bundle, ephemeris latency and projection/label-layout cost before claiming an improvement.
