# Nearby aircraft: sources, delivery and methods

Decision date: **October 5, 2026, America/New_York (EDT, UTC−04:00)**. UTC timestamps below are retained for reproducibility. This document supersedes the initial research recommendation to prefer adsb.fi: **AvioADSB remains the default because its current browser delivery was verified; adsb.fi is an explicit experimental alternate whose current delivery failed.** No paid service, account, secret key or alternative hosting platform was introduced.

The application already had AvioADSB polling and camera-projected aircraft markers. This work adds bounded nearby selection, stronger altitude/position handling and visible controls by reusing that architecture. Aircraft positions come from community radio telemetry, not recognition of aircraft in camera images. Frames stay on the device. Successful data delivery does not establish coverage, physical pointing accuracy or visibility through terrain/clouds.

## Exact nearby endpoints and schema basis

The controlled delivery checks used only a fixed public London point, latitude 51.507°, longitude −0.128°, radius 25 nautical miles:

- Default: `https://avioadsb.org/v1/point/51.507/-0.128/25`
- Experimental: `https://opendata.adsb.fi/api/v3/lat/51.507/lon/-0.128/dist/25`
- Researched only: `https://api.adsb.lol/v2/point/51.507/-0.128/25`
- Researched only: `https://api.airplanes.live/v2/point/51.507/-0.128/25`

The adsb.fi README states: **“The endpoints and responses are compatible with ADSBexchange v2 API.”** It lists the v3 nearby endpoint and explains that the differently formatted v2 nearby endpoint is deprecated. This is the documented basis for using the compatible **`ac` array and millisecond `now`** adapter for v3, with strict validation. It is **not a successfully sampled v3 response**. If the live response does not satisfy that contract, the parser fails closed rather than guessing another format or inventing freshness. No mandatory User-Agent identification requirement was found in the inspected README; the 403 was not diagnosed as a missing User-Agent. No identity spoofing, bypass or retry sequence followed the denial.

The upstream readsb specification makes a critical distinction:

| Field | Ordinary `aircraft.json` | ADS-B Exchange v2-compatible output / current provider adapter |
|---|---|---|
| Array | `aircraft` | `ac` |
| Top-level `now` | Unix **seconds** | Unix **milliseconds** |
| `seen_pos` | Seconds before `now` of the most recent position | Same meaning |
| `seen` | Seconds since any message; not position freshness | Same meaning |
| `alt_geom` | Geometric GNSS/INS altitude in **feet above WGS84 ellipsoid** | Same compatible field convention |
| `alt_baro` | Barometric altitude in **feet**, or string `ground` | Same compatible field convention |
| `gs`, `track` | Knots; true ground track in degrees | Same compatible field convention |
| `geom_rate`, `baro_rate` | Feet per minute, with distinct altitude conventions | Same compatible field convention |

`positionAt = providerAt − seen_pos × 1000`; receipt time does not replace provider time. The parser retains source type and integrity fields, excludes ground reports, checks finite coordinates/altitudes, bounds response size and range, and does not promote rough coordinates or `lastPosition` into a fresh fix. Optional fields can be absent. Callsign or transponder identifiers are data labels, not visual identifications or complete flight-route information.

## Accuracy and mechanics

`js/aircraft-geometry.js` uses WGS84 geographic-to-ECEF ([EPSG method 9602](https://epsg.io/9602-method)), followed by local ENU ([ESA Navipedia](https://gssc.esa.int/navipedia/index.php/Transformations_between_ECEF_and_ENU_coordinates)). Observer `heightM`, when supplied, is ellipsoid height; absent height is explicitly **assumed zero**, not a measured ground elevation. Geometric aircraft altitude is preferred. A barometric fallback is labelled approximate because pressure altitude is being used as an ellipsoid-height substitute; there is no QNH/geoid/refraction correction.

Ground-range selection uses Vincenty's WGS84 inverse distance for nearby queries. Nonconvergence is excluded, not fabricated. Altitude/azimuth and slant range derive from the observer-relative ECEF vector; directly overhead/coincident azimuth limits are explicit. This improves coordinate geometry but cannot correct wrong feed positions, unknown terrain, phone compass errors or lens calibration.

Between reports, available true track, ground speed and matching vertical rate drive a **constant-velocity estimate capped at fifteen seconds**. Turns and acceleration are unknown. After fifteen seconds the estimate holds, avoiding a backward jump to the old reported position; after **twenty seconds**, the record is ineligible for the camera overlay. List records expire after **sixty seconds**. A five-second future-clock tolerance is bounded separately. These are application policies, not claims about provider accuracy. Numeric geometry is deterministic; radio coverage and sensor alignment remain empirical limitations.

`node tests/aircraft-nearby.mjs` was independently run during this documentation pass: **12 groups passed**. Coverage includes a published EPSG Cartesian reference within one centimetre, ENU cardinal/zenith limits, distance references, explicit timestamp schemas, combined position age, altitude preference and qualifications, fifteen-second motion cap, lifecycle cancellation, persistent 401/403/429 pauses and malformed-input handling. Those tests do not prove live aircraft coverage or physical camera alignment. Integrated browser, visual and phone checks remain release gates documented separately.

## Lifecycle, privacy and maintenance contract

- Aircraft requests begin only after an explicit on/off control and a usable selected observer. Requests send rounded coordinates, radius and the connection's IP to the **selected** provider. State the recipient and attribution beside its control. Use no credentials/referrer and do not store raw position histories by default.
- No automatic provider failover. A deliberate user switch may disclose coordinates to a new recipient; toggling off, backgrounding or choosing simulated time stops polling and releases pending work. A failed or quota-paused feed must not remain labelled live.
- AvioADSB reset headers are durations in seconds. Honour `Retry-After`, expose remaining quota when supplied and retain cooldowns across controller restarts. Anonymous network quotas are shared; a local counter cannot guarantee allowance. Stop repeated 401/403/429 requests; do not rotate addresses, headers or identities to evade limits.
- Recheck provider documentation before changing cadence, radius, authentication or redistribution. The current source review did not audit every upstream release or guarantee maintenance. Public GitHub Pages cannot conceal a private API key. Keep the provider adapter small and separate from renderer, sensor and local ephemeris loops.
- Useful unavailable states are part of the product: no nearby reports, stale positions, unavailable provider, quota pause, simulated-time suspension and unsupported location. None means all aircraft are known or the sky is empty. This is an observing aid, not navigation or aviation safety equipment.

Remaining limitations: AvioADSB's short anonymous allowance remains unresolved for sustained all-evening use; experimental adsb.fi access is currently unverified/blocked under the tested conditions. Neither open-source software nor an alternate endpoint removes service terms or permits bypass. Own-receiver support and further providers remain explicit future integrations with their own permissions, delivery tests and maintenance cost.
