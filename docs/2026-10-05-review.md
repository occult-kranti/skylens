# Hindi names and observing review — 2026-10-05

Bounded independent review of `js/names.js`, `js/observing.js`, saved-location input/persistence in `js/main.js`, and their immediate UI integration. One findings pass and one repair confirmation; no implementation edits by this reviewer. This is not a replacement for the release browser/screenshot gate or a physical-phone alignment test.

## Findings and disposition

1. **Next-event cache crossed a real event boundary — repaired.** The initial main coordinator keyed observing results by minute. For the Sun at London 51.5°N, 0°E on 2026-10-05, a request at `06:07:05.273Z` returns sunrise around `06:07:06.167Z`; a request at `06:07:07.273Z` must instead return the next sunrise, `2026-10-06T06:08:45.499Z`. Both requests previously shared a cache key and could display an already-past event as the next event. The coordinator now keys by the exact requested `date.getTime()`, object identity and coordinates. The repaired source separates these requests while retaining reuse for a frozen simulated instant. Calculations run on explicit object-detail requests, not the animation loop.
2. **Unavailable-event presentation exposed machine codes — repaired.** The initial object-details error branch displayed `unsupported-object` or another error code and dropped the explanatory `note` supplied by the calculation module. The corrected branch prioritizes that human-readable note, filters machine codes from fallback prose, preserves unavailable/error state and clears the loading indicator. Source repair and controller syntax were confirmed; the real browser journey remains a release gate. This affects unsupported deep-sky objects and failed calculations; it does not fabricate numerical output.

No other material blocker was found in this bounded numerical/naming/location review. The solar-origin HYG row `Sol` is now excluded by the catalogue loader after stable raw-row IDs are assigned; it cannot become a false stationary Sun or shift saved-star identities. Saved locations preserve zero coordinates, reject nonfinite/out-of-range positions, bound names/counts, and report session-only storage when persistence is unavailable.

## Naming source check

The reviewer independently fetched the primary [NCERT Curiosity, Beyond Earth, reprint 2026–27](https://ncert.nic.in/textbook/pdf/fecu112.pdf), pages 234–236. It explicitly associates Betelgeuse with Ārdrā, Aldebaran with Rohiṇī, and Polaris with Dhruva tārā; it separately calls Kṛittikā the Pleiades **group**. The implementation's traditional aliases are limited to these supported cases. Other reviewed star spellings are disclosed editorial Devanagari transliterations; unsupported names retain their catalogue name. Canonical calculation names and stable object IDs remain unchanged. Moon's common Hindi spelling has editorial provenance instead of incorrectly attributing its literal spelling to the English textbook.

The [All Skies Encyclopaedia Rohiṇī entry](https://ase.exopla.net/index.php/Rohini) independently clarifies that the term also describes an asterism/lunar-mansion tradition and that Aldebaran is not physically a Hyades cluster member. The implementation's alias note correctly avoids equating an individual star with an entire nakshatra asterism or zodiac sector. Polaris is labeled as the present-day pole star, not every historical pole star. Canopus/Mizar/Alcor have transliterations only in this bounded release; no unsupported traditional mapping was invented.

Source discovery used three distinct Exa searches requesting 15 candidate results, followed by direct primary/source-page retrieval. Search results were discovery material, not treated as independently validated claims.
